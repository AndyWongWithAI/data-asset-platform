# 数据资产门户 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增「数据资产门户」SPA，作为「数据资产管理平台」的业务侧「一体两面」——共享同一份种子数据与后端，两个独立 SPA 互为切换。

**Architecture:** 单仓库 Vite 多入口（两个独立 build/两个 base）。新增 `portalAssets` / `portalRequests` 两个只读实体（`store.js` READABLE 自动收录，无需改后端代码）；管理平台加「门户管理」模块；门户侧新建 `src/portal/` 一套业务化组件。

**Tech Stack:** React 18 + Vite 5（多 config 双入口）+ Express 5 后端（JSON 落盘，无需改动）+ Playwright 冒烟。

## Global Constraints

- 引用完整性是硬约束：`tableIds`/`serviceIds` 必须存在于 `tables`/`services`，且 `tableIds ∪ serviceIds ≠ ∅`；改动任何 id 必同步改引用。
- 治理一致性：`portalAsset.securityLevel >= max(打包对象有效分级)`，用 `LEVEL_RANK` 断言（表取 `max(字段 securityLevel)`，服务取 `service.securityLevel`）。
- `meta.disclaimer` 声明不变；不虚构内部运营数据（业务方/专员/管理人员一律用**角色占位**，不用真实人名）。
- 审批流与申请动作本次均 demo 化（静态 `approval` 数据 + `ComingSoonAction` 占位），不做真实写流转。
- 不触碰广发「数据资源目录」术语。
- git-guardrails L0：`main` 只接受 merge 提交；每个 Task 结束在 task 分支提交，最后统一 merge。
- 每次开发完成必须跑 `npm run test:page`（管理平台）+ 新增 `npm run test:portal`（门户）。
